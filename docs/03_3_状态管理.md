# 03_3. 状态管理 (Zustand)

本文档详细介绍聪言前端应用中使用的全局状态管理方案。

## 1. 方案选型

项目采用 [**Zustand**](https://github.com/pmndrs/zustand) 作为全局状态管理的解决方案。Zustand 是一个轻量、快速、可扩展的状态管理库，它基于 Hooks，API 简洁，能以极小的代码量实现高效的状态管理，且没有 Provider 嵌套地狱的问题。

## 2. Store 结构

项目中所有的全局状态都按业务领域被划分到 `src/store/` 目录下的不同文件中，每个文件代表一个独立的 "Store"。这种模式使得状态逻辑清晰，易于维护。

以下是项目中定义的核心 Stores：

- `auth.ts`: 管理用户认证信息。
- `input.ts`: 管理全局输入状态。
- `chat.ts`: 管理聊天界面的消息状态。
- `tasks.ts`: 管理患者的任务列表状态。

## 3. 核心 Stores 详解

### 3.1. `useAuthStore` (`auth.ts`)

这是最核心的 Store，负责整个应用的认证状态和用户信息。

- **State**:

  - `isAuthenticated: boolean`: 标记用户是否已登录。
  - `userInfo: UserInfo | null`: 存储当前登录用户的详细信息。
  - `token: string | null`: 存储从后端获取的 JWT。
  - `tokenExpiry: number | null`: 存储 token 的过期时间戳。

- **Actions**:
  - `login(...)`: 登录成功后调用，将 token 和过期时间存入 `localStorage` 和 store。
  - `logout()`: 清除 `localStorage` 和 store 中的所有认证信息。
  - `checkAuth()`: 应用初始化时调用，检查 `localStorage` 中是否存在有效的 token，用于恢复用户登录状态（会话保持）。
  - `fetchUserInfo()`: 异步 action，调用 API 获取最新的用户信息并更新到 store 中。

### 3.2. `useInputStore` (`input.ts`)

这是一个极简的 UI 状态 Store，用于优化特定场景下的用户体验。

- **State**:

  - `input: boolean`: 标记是否有输入框（如聊天输入）处于激活状态。

- **Actions**:
  - `setInput(boolean)`: 设置 `input` 状态。

在 `App.tsx` 中，会监听此状态。当 `input` 为 `true` 时，隐藏底部导航栏，为输入区域提供更多空间。

### 3.3. `useChatStore` (`chat.ts`)

此 Store 专为聊天功能服务，特别是为流式响应做了优化。

- **State**:

  - `messages: Message[]`: 存储当前对话的所有消息对象。

- **Actions**:
  - `addMessage(message)`: 添加一条新消息。
  - `appendContentToMessage(id, contentDelta)`: **核心功能**。向指定 `id` 的消息追加一小段文本。这对于处理类似大语言模型的流式输出至关重要，可以实现文本逐字显示的效果。
  - `markMessageAsStopped(id)`: 当流式响应被中断时，标记该消息。

### 3.4. `useTasksStore` (`tasks.ts`)

此 Store 用于管理从后端获取的数据列表，并包含了加载和错误状态。

- **State**:

  - `tasks: PracticeTaskInfo[]`: 存储患者的任务列表。
  - `loading: boolean`: 标记数据是否正在加载中。
  - `error: string | null`: 存储数据加载过程中的错误信息。
  - `fetchAttempted: boolean`: 一个优化标志，用于避免对同一数据的重复请求。

- **Actions**:
  - `fetchTasks(patientId)`: 异步 action，根据 `patientId` 从后端获取任务列表，并自动管理 `loading` 和 `error` 状态。
  - `clearTasks()`: 重置整个 store 的状态，以便下次可以重新获取数据。
