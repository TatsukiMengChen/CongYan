# 05. 部署与构建

本文档提供了为聪言项目进行生产环境构建和部署的说明。项目支持两种主要的部署目标：**跨平台桌面应用**和**纯 Web 应用**。

## 1. 桌面应用打包 (Tauri)

将项目打包成原生桌面应用（如 `.exe`, `.dmg`, `.AppImage`）是主要的发布方式。

### 1.1. 前提条件

- 确保已根据 [Tauri 官方文档](https://tauri.app/v1/guides/getting-started/prerequisites) 完成了特定操作系统的所有环境依赖配置（如 `build-essential`, `libwebkit2gtk-dev` on Linux, `Xcode Command Line Tools` on macOS, `Microsoft C++ Build Tools` on Windows）。

### 1.2. 构建命令

在项目根目录下，执行以下命令：

```bash
pnpm tauri build
```

### 1.3. 命令执行流程

1.  **`pnpm build`**: 首先，该命令会自动执行 `tauri.conf.json` 中 `beforeBuildCommand` 定义的脚本，即 `pnpm build`。这会调用 Vite 来构建和优化前端 React 应用，并将产物输出到 `/dist` 目录。
2.  **Rust 编译**: 接着，Tauri 会编译 `src-tauri/` 目录下的 Rust 代码。
3.  **应用打包**: 最后，Tauri 会将编译好的前端产物 (`/dist`) 和后端二进制文件"捆绑"在一起，并根据当前操作系统生成相应的安装包或可执行文件。

### 1.4. 构建产物

- 构建完成后，最终的安装包会存放在 `src-tauri/target/release/bundle/` 目录下。
- 例如，在 Windows 上会生成 `.msi` (安装器) 和 `.exe` 文件；在 macOS 上会生成 `.dmg` 文件。

## 2. Web 应用部署

项目同样可以作为一个标准的单页面应用 (SPA) 部署到任何静态 Web 服务器上。项目根目录下的 `deploy.sh` 脚本提供了一个自动化部署到特定测试服务器的示例。

### 2.1. 部署脚本 (`deploy.sh`)

该脚本执行了一套标准的 Web 部署流程，主要用于将应用部署到一个基于 `openresty` 的预发布环境 (`pre.cy.mimeng.top`)。

### 2.2. 部署流程详解

1.  **安装依赖**: `npm install`
2.  **执行构建**: `npm run build:test`。这会调用 Vite 对前端代码进行构建，生成用于生产环境的静态文件。
3.  **同步文件**:
    - 使用 `rsync -avz --delete` 命令。
    - 将 `/dist` 目录下的所有内容强制同步到服务器的目标路径 `/opt/1panel/apps/openresty/openresty/www/sites/pre.cy.mimeng.top/index`。
    - `--delete` 参数会确保目标目录与源目录完全一致，删除目标目录中多余的文件。

### 2.3. 手动部署

如果你需要将 Web 版本部署到其他服务器，可以手动执行以下步骤：

1.  在项目根目录运行 `pnpm build`。
2.  将生成的 `/dist` 目录下的所有文件上传到你的 Web 服务器的网站根目录。
3.  确保服务器配置了对单页面应用 (SPA) 的支持，即所有未匹配到静态文件的路由请求都应重定向到 `index.html`。
