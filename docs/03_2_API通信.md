# 03_2. API 通信

本文档描述了聪言前端应用如何与后端服务器进行数据交互，包括底层的 HTTP 客户端配置和上层的 API 请求封装。

## 1. HTTP 客户端 (`src/utils/http.ts`)

为了实现统一、可维护的API请求，项目封装了一个全局的 HTTP 客户端。该客户端基于 [Axios](https://axios-http.com/) 创建，并进行了标准化配置。

### 1.1. 核心配置

- **基础URL (`baseURL`)**: 所有API请求的基础路径都是通过 Vite 的环境变量 `import.meta.env.VITE_API_URL` 来设置的。这使得应用可以轻松地在开发、测试和生产环境之间切换不同的后端服务地址。
- **默认头部 (`headers`)**: 默认设置 `Content-Type` 为 `application/json`。

### 1.2. 拦截器 (Interceptors)

拦截器是本模块的核心，它可以在请求发送前或响应返回后，对数据进行全局处理。

#### 请求拦截器 (`request interceptor`)

在每个HTTP请求被发送到服务器之前，请求拦截器会自动执行以下操作：

1.  从 `localStorage` 中读取名为 `token` 的 JWT。
2.  如果 `token` 存在，则将其以 `Bearer ${token}` 的形式添加到请求的 `Authorization` 头中。

这确保了所有需要认证的API请求都能自动携带身份凭证，无需在每个请求中手动添加。

```typescript
// src/utils/http.ts
http.interceptors.request.use((config) => {
  const token = localStorage.getItem("token");
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});
```

#### 响应拦截器 (`response interceptor`)

在收到服务器的响应后，响应拦截器会进行全局的错误处理，特别是针对认证失败的情况：

1.  检查响应体中是否包含业务定义的错误信息，如 `message === "no auth"`。
2.  检查响应的 HTTP 状态码是否为 `401 Unauthorized`。

一旦满足以上任一条件，拦截器会：

- 从 `localStorage` 中移除无效的 `token`。
- 将用户重定向到 `/login` 页面，要求重新登录。

这种机制保证了用户认证状态的及时更新，并提供了统一的错误处理流程。

## 2. API 模块化 (`src/api/`)

项目中所有的API请求都按照其业务领域，被组织在 `src/api/` 目录下的不同文件中（如 `auth.ts`, `user.ts`, `chat.ts` 等）。

这种模块化的方式有以下优点：

- **高内聚、低耦合**: 相关功能的API集中在一起，方便查找和维护。
- **职责清晰**: 每个文件只负责一个业务领域的API，结构清晰。
- **易于扩展**: 新增业务功能时，只需创建新的API文件即可。

### 2.1. API 定义示例

以 `src/api/auth.ts` 为例，一个典型的API模块包含以下部分：

1.  **导入 `http` 实例**: 从 `../utils/http` 导入已配置好的 Axios 实例。
2.  **类型定义**: 使用 TypeScript 为请求参数和响应数据定义精确的类型，以实现类型安全。
3.  **API函数封装**: 将每个API端点封装成一个独立的、可导出的 `async` 函数。

```typescript
// src/api/auth.ts

import http from "../utils/http";

// 1. 定义响应数据的 TypeScript 类型
export type LoginAPIRes = {
  status: number;
  data?: {
    jwt_token: string;
  };
  message?: string;
};

// 2. 定义请求体的 TypeScript 类型
export type PasswordLoginReqBody = {
  phone_number: string;
  password?: string;
};

// 3. 封装并导出 API 请求函数
export const PasswordLoginAPI = async (
  body: PasswordLoginReqBody,
): Promise<LoginAPIRes> => {
  try {
    const res = await http.post<LoginAPIRes>("/password-login-detail", body);
    return res.data;
  } catch (error: any) {
    // 处理特定于此API的错误
    return error.response?.data;
  }
};
```

通过这种方式，业务逻辑层（如React组件或Hook）可以像调用一个本地函数一样调用 `PasswordLoginAPI`，而无需关心 `axios` 的具体实现细节。
