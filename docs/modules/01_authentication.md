# 核心功能: 01. 认证模块 (Authentication)

本文档详细解析聪言应用的认证模块，包括用户注册、登录的流程、核心组件和业务逻辑。

## 1. 模块概述

认证模块位于 `src/pages/auth`，是用户进入应用的门户。它提供了安全、健壮的用户身份验证流程，并集成了人机验证以增强安全性。

- **主要页面**:
  - `login.tsx`: 用户登录页面。
  - `register.tsx`: 新用户注册页面。
- **核心技术**:
  - **API**: `src/api/auth.ts`
  - **状态管理**: `src/store/auth.ts` (Zustand)
  - **人机验证**: 极验 (Geetest)，通过自定义 Hook `useCaptcha` 封装。

## 2. 共享组件 (`src/pages/auth/components`)

为了保证UI的一致性和代码的高度复用，认证模块抽象出了一系列共享组件：

- **布局容器**: `AuthContainer.tsx`, `AuthCard.tsx`, `AuthHeader.tsx`。
- **原子化输入框**: `PhoneInput.tsx`, `PasswordInput.tsx`, `VerificationCodeInput.tsx`, `UsernameInput.tsx` 等。
- **选择器**: `BirthDatePicker.tsx`, `GenderSelect.tsx`, `RoleSelect.tsx`。
- **策略勾选**: `PolicyCheckbox.tsx`，用于处理用户协议和隐私政策的同意逻辑。

## 3. 用户登录流程 (`login.tsx`)

登录页面提供两种登录方式，并贯穿了人机验证和全面的用户反馈。

1.  **登录方式切换**: 用户可以在"短信验证码登录"和"密码登录"之间自由切换。

2.  **验证码登录流程**:

    - **步骤 1: 请求验证码**:
      - 用户输入手机号，点击"获取验证码"。
      - **客户端校验**: 检查手机号格式是否正确。
      - **人机验证**: 触发 `useCaptcha` Hook，弹出极验验证窗口。
      - **状态检查**: 人机验证通过后，调用 `CheckRegisteredStatusAPI` 确认该手机号**已注册**。
      - **发送请求**: 确认已注册后，调用 `AskCodeAPI` 请求后端发送短信验证码。
      - **用户反馈**: 显示60秒倒计时，防止重复发送。
    - **步骤 2: 提交登录**:
      - 用户输入6位验证码。
      - **人机验证**: 再次触发极验验证。
      - **API 调用**: 调用 `SmsLoginAPI` 提交手机号和验证码。

3.  **密码登录流程**:

    - 用户输入手机号和密码。
    - **人机验证**: 触发极验验证。
    - **API 调用**: 调用 `PasswordLoginAPI` 提交手机号和密码。

4.  **登录成功处理**:
    - 无论哪种方式，登录成功后后端会返回 `jwt_token`。
    - 前端使用 `jwt-decode` 库解析 token，获取用户角色、ID等信息。
    - 调用 `useAuthStore` 的 `login` Action，将认证信息存入全局状态和 `localStorage`。
    - 导航至应用主页 (`/`)。

## 4. 用户注册流程 (`register.tsx`)

注册流程设计为一个分步表单，引导用户完成信息填写。

1.  **步骤一：验证手机号**:

    - 用户输入手机号，点击"下一步"。
    - 此步骤的核心是确认手机号的可用性，为下一步发送验证码做准备。
    - 这里的逻辑与登录页类似，会先检查手机号是否**未被注册**。

2.  **步骤二：填写信息与验证**:

    - 用户填写个人信息（角色、出生日期、性别）。
    - 用户获取并填写短信验证码（此处的逻辑与登录页的验证码获取流程完全相同）。
    - 点击"注册"按钮。

3.  **提交注册**:

    - **客户端校验**: 检查所有字段是否填写正确。
    - **人机验证**: 触发极验验证。
    - **API 调用**: 调用 `RegisterAPI`，将所有用户信息和验证码一次性提交到后端。

4.  **注册成功即登录**:
    - 注册成功后，后端直接返回 `jwt_token`。
    - 前端执行与登录成功后完全相同的逻辑：解码 token -> 更新 `useAuthStore` -> 导航至主页。这实现了"注册成功后自动登录"的无缝体验。
